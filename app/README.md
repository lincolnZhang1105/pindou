# app：豆伴安卓原型

> **这是原型，不是阶段 1 的 App。**
> PO 在 2026-10-31 决定：go/no-go 还没判定时，先做一个只装在 PO 自己手机上的安卓原型，用来在真机上试识别效果，并顺带测 T0.14 的真机耗时。
> 范围和约束见 `docs/07-roadmap-and-tasks.md`「例外：安卓原型」。正式的 T1.x 仍然要等 go 结论；如果开工，可以在这个工程上继续做，但要按 T1.1 的 DoD 补齐。

## 能做什么

- **导入图纸**：用系统图片选择器（Android 13 起是 Photo Picker），不申请相册权限。可以多选，分页图按页码顺序选。
- **识别**：在后台 Isolate 里通过 `dart:ffi` 调用 `libbeadcore.so`。图片用 Flutter 的解码器按原尺寸解码，不压缩、不缩小。
- **看结果**：
  - 网格尺寸、豆子数、色号数、判断的品牌、耗时；
  - 图例核对；
  - 可缩放的重画图纸（不确定的格子描红框，放大后显示色号）；
  - 用量清单（和图例颗数对照）。
- **点一个色号**：只高亮这个色号的格子，这是最小版的「高亮跟拼」。
- **用内置测速图测一下速度**：104×104 的标准图，程序生成、没有版权问题，用于 T0.14。

## 不做什么

账号、付费、后端、联网、埋点、崩溃上报、图纸库、编辑、完整的跟拼。

- 安装包**不声明网络权限**，也不申请相册、存储、蓝牙权限。
- 安装包里只有 `palettes/` 里核实过来源的 12 套国际色卡。
- 测 MARD 等国内品牌的图纸时，用 `tools/app-push-palettes.sh` 把 bench 测试色卡推到手机上 App 的专属目录。这份色卡不进安装包。

## 编译和安装

1. 在 WSL 里编出 Android 版的识别库：`tools/build-android.sh`。
2. 在 Git Bash 里打包：`tools/build-app.sh`。它会把原生库、模型、色卡、测速图拷进来（这些都在 gitignore 里），然后执行 `flutter build apk`。
3. 手机打开 USB 调试并连上电脑，然后安装：`adb install -r app/build/app/outputs/flutter-apk/app-release.apk`。
4. 需要测试色卡时运行：`tools/app-push-palettes.sh`。

## 在电脑上的安卓模拟器里测

模拟器是 x86_64 的。arm64 识别库在 ARM 转译下一加载 ONNX Runtime 就崩，这只是模拟器的问题，所以要另编一个 x86_64 版：

1. 编识别库：`ABI=x86_64 tools/build-android.sh`；
2. 打双架构的测试包：`APP_ABIS="arm64-v8a x86_64" tools/build-app.sh`；
3. 用 `adb install` 安装。

给手机的包仍然只用默认的 arm64。

## 已在模拟器上验证（2026-10-31）

- 内置测速图：104×104，与图例完全一致。
- 从系统选择器导入 3_0：
  - 58×53，与图例完全一致；
  - 结果页显示「原图：1080×1241，1065 KB」，和原文件大小一致，说明导入时没有被压缩；
  - 推送测试色卡后，品牌认成 MARD-221，色号写法也正确。
- 点色号高亮正常。

## 已知限制（原型）

- **品牌判断**：只有内置色卡时，MARD 等国内品牌的图纸品牌显示「未确定」（置信度低于 0.5），色号写法也可能被改成最接近的国际色卡的写法。要测这类图纸，先推测试色卡。
- **标题是缓存文件名**：结果页标题是系统选择器复制出来的文件名（比如 `34.png`），不是原名。
- **只有 arm64-v8a**，minSdk 26（Android 8.0）。
- **ONNX Runtime 用的是官方完整版**（34 MB）。正式版要换成 `--no_telemetry`、只含所需算子的精简构建。
- **签名用的是 debug 密钥**，只能 adb 安装，不能上架。
- **拼图（`needs_user_crop`）只能提示**，不能框选。
- **JPEG 的 EXIF 方向（待核实）**：没有在真机上确认 `instantiateImageCodec` 是否按 EXIF 方向转正。从小红书保存的图一般没有方向标记。
